## 3. What "one explicit result contract per producer" is in this codebase

### 3.1 Shape

Per callable (source function, variant, class member, dispatcher, closure id, closure set), frozen once:

```
ResultContract = {
  kind:     K (the summary's tag set, presence bits included: resultOf),   // already exists
  presence: PRESENT | MAYBE_UNDEF | MAYBE_NULL  (projection of NULLISH/ABSENT in kind),
  carrier:  i32 | f64 | ptr(kind, aux) | RAW_I64 | BOXED | ANY,           // new
  abi:      the wasm result type(s) this carrier implies (sig.results, ptrKind/ptrAux, unsignedResult)
}
```

`carrier` rules, decided from `kind` alone plus the ABI class, no body walk:

- kind ⊆ {NUMBER} and the range channel proves i32 → `i32` (today's `narrowI32Results` verdict, kept as the ABI half); else `f64` raw.
- kind = one pointer tag with a known param → `ptr(tag, aux)` (today's `narrowPointerResults`).
- kind = {BIGINT} exactly, callable is direct-only (not exported, not value-used, not a closure, not a dispatcher) → `RAW_I64` (today's `representationResultRawBigint` + `paramRawOnly`-style census, made a rule: every direct call site is enumerable, so RAW is sound).
- kind ∋ BIGINT and anything else, or the callable is a closure/dispatcher/exported/value-used → `BOXED` (today's `forceTaggedResult`, `taggedUnion`, `genericCallBoxed`, `isTaggedCallResult` collapsed into one rule).
- kind ∋ BOOL and the ABI is f64 → the atom form is part of the carrier (today's `boxedResult`/`mixedAtomReturn`/`resultBool`): `f64` with atoms, or `i32` when kind = {BOOL} and the callable is direct-only.
- kind = NONE (never returns / diverges) → `f64` with presence MAYBE_UNDEF (bare fallthrough already raises NULLISH at index.js:1062).

Per producer expression, derived (not stored): `E(expr) = { kind: kindOfExpr(expr), presence, carrier }` where the carrier follows the producer class: a literal/origin RAW, a call its callee's `carrier`, a slot read the slot's carrier (typed element RAW, tagged array/map/hash slot BOXED, schema slot per the slot's own contract), an arithmetic node RAW when every operand is BIGINT else the joint form, a join the join of its arms unless they differ (then BOXED), a name its binding's carrier. This is exactly the table `currentOf` (body-data.js:363-422) computes ad hoc, restated as a pure function of contracts.

### 3.2 Where it is computed

In the summary's freeze, after variants, closures and dispatchers close: `summarize` (index.js:81) already computes `results` for every function name and closure id (index.js:893, :1062-1063) and joins closure sets (:328-332). The freeze step adds `carrier` per key from `results`, `escaped` (index.js:89, :110), the export set (`exported(f)`), the value-used set (`ProgramIndex.addressTaken`, program-index.js) and the dispatcher flag, and publishes it into ProgramIndex next to `functionBoundaryData` (program-index.js:590-620) so a callable identity (source/variant/anonymous) owns it. The third `summarize` at compile/index.js:297 is the one emission reads; the boundary solver (plan/index.js:280) must move after it or read it (risk 4.5).

The range/ABI half (`i32`, `v128`, pointer aux, `unsignedResult`) stays in narrow until the range domain lands; the contract records the outcome, and `attachSigMeta`/`exprType` keep reading `sig` (the two kept sites).

### 3.3 Where it is read

One query on the settled solution: `summary.resultContract(idOrName)` beside `resultOf`, and `summary.at(scope).producer(expr)` returning `E`. Plan consumers: `semanticOf`/`currentOf`/`plannedOf` become lookups; `edgeAction(E(source).carrier, target.carrier)` is the whole edge decision. Emit consumers: `readI64(node, ir)` asks `E(node).carrier === BOXED`; `applyBigintRepresentationAction` loses its gate; the `'return'` handler converts `E(tail)` to the callable's `carrier`; the host wrapper's lane is `f(contract)`; the trampoline reboxes from `contract`.

## 4. Risks visible in the code

4.1 **Recursion / SCC results.** The summary raises `results` monotonically across rounds (index.js:893 `raise`), so a recursive function's result is the join over the fixpoint and a self-call reads `K.NONE` on round one (call at index.js:303 returns `results.get(callee) ?? K.NONE`). That is correct for kinds. A carrier derived from the joined kind is stable, but `narrowI32Results` breaks its own cycle optimistically (results.js:202-213) and reanalyzes; a contract with an ABI half must either keep that optimism as a separate range step or accept f64 for self-recursive numeric results. The plan's `materializedResult` for mutually recursive callees depends on build order (body-data.js:383-388: "falls open to the boundary's current when the body isn't there yet"), which a frozen contract removes; the risk is byte churn in recursive kernels (the op-count ratchet, `test/perf-ratchet.js`).

4.2 **Closure sets with mixed results.** `closureResult` joins members (query.js:27-31, index.js:328-332); a set past `SET_MAX` (32) escapes every member (index.js:131), and an escaped closure's parameters go ANY (index.js:1269) while its result stays whatever its body returns. A set whose members return Number and BigInt gets kind {NUMBER, BIGINT} → carrier BOXED, which agrees with `forceTaggedResult`. The hazard is the inverse: a set whose members all return {BIGINT} would be RAW under a naive rule; closures must be BOXED unconditionally (the ABI slot is `f64` `$ftN`, closure-emit.js:30-35), so the rule in 3.1 keys on "closure" before "kind". `tagDynamicMethodResult` (method-dispatch.js:716-743) shows the other side: a named function reached through a property has a RAW result the caller re-tags by funcidx; under the contract that function is value-used and BOXED at its trampoline, so member 2 of the withdrawn experiment (kinds of value-used functions' parameters, PLAN.md:676-679) is not touched.

4.3 **`any` parameters.** An `any` parameter (`escaped` → ANY, index.js:1264, :1269; a host parameter, :1280) makes every arithmetic on it {NUMBER, BIGINT} (kind.js:78-92 `arith` with `COERCION_UNKNOWN`), so results of functions over `any` become BOXED even when the program never passes a BigInt. That is the "cost of required boxes at previously incorrect edges" PLAN.md:233-236 already accepts; the numeric-demand pass (index.js:1068-1252, `numericDemand`/`numericDenied`) narrows a demanded parameter to NUMBER before the second fixpoint (:1298-1304), which is the mechanism that keeps the flagship numeric. A contract must be computed after that rerun, never from the first fixpoint. The ledger §11 shape (`slebSize(v)`, v of every kind) is the pin: the parameter's kind is ANY, its carrier BOXED, and the callee's reads must unbox by tag (`readI64` tag test), which the contract keeps as the one runtime test.

4.4 **Host boundary (`jz:hostabi`, `jz:i64exp`).** Today the result lane is chosen from six inputs (boundary-wrap.js:84-95) and the interop side decodes by `r` (compile/index.js:806-815). A RAW_I64 result crosses unmarked; a BOXED one marked. Changing a result from raw to boxed (or the reverse) changes the export's wire contract and every retained-output test (test/imports.js A→A→B, test/sequence-values.js:163 bare-return bytes, `dist/jz.wasm` parity in test/kernel-parity.js). `paramRawOnly` for exports is always empty (index.js:824-838), so the parameter side has one state (`tag`) and is not at risk; the result side is.

4.5 **Three summaries, one copy.** `seedResultKinds` copies `resultOf` into `func.valResult` at plan/index.js:198 or narrow/index.js:115 (the second summary), `solveRepresentationBoundaries` reads `ctx.summary.resultOf` at plan/index.js:280 (still the second summary), and emission reads the third summary (compile/index.js:297) built after the plan's rewrites (inlined calls, variants). A contract frozen in the second summary describes a program that no longer exists at emit; frozen in the third, the boundary solver must move after compile/index.js:297. `narrowSignatures` mutates `sig.results/ptrKind` (results.js:216-227, :294-307) between the two, so the ABI half must be recomputed on the third summary or carried by identity through ProgramIndex variants.

4.6 **Array `reduce` and callbacks the summary does not bind.** `ARRAY_CALLBACKS` (index.js:405) omits `reduce`/`reduceRight`; only TYPED `reduce` has the accumulator recurrence (`reduceResult`, :388-401). module/array.js:1919-1949 seeds the accumulator's kind from `valTypeOf(init)` and stores the inline callback's raw value (`asF64(cb.call(...))`, :1934). The exit case "optional BigInt-array reduce with a Number accumulator" (test/data.js:400) passes today for TYPED receivers only; an ARRAY receiver's reduce has no contract at all. The same gap applies to `sort` comparators, `flatMap`, `find` callbacks on non-array receivers, and any callback the summary escapes (`escapeArgs` at :408, :448).

4.7 **The kernel's own shapes.** `slebSize` (families :22) and watr's `i64.parse`/`encode.i64` (provenance.js:99-113, :506-527 comments; test/data.js:2578-2720) are the shapes that broke both withdrawn attempts. The specific hazards for a contract rollout: (a) a parameter reassigned from a storage read (`n = nodes.shift()`) whose carrier is BOXED while its kind is {STRING, NUMBER, BIGINT}: the binding's carrier must be BOXED and every `n & 0x7fn` must `readI64` by tag; (b) a `let x = typeof v === 'bigint' ? v : BigInt(v)` join whose kind the summary can name (BIGINT via `refined` masks, index.js:1003-1024) but whose arms differ in carrier (a BOXED parameter vs a RAW origin): the join's contract is BOXED and the binding's RAW only if every def is RAW, so `x` is BOXED here and `x >>= 7n` reads by tag (the ledger §11 fix keeps this); (c) `indirectResult` (provenance.js:190, :312, :554-560) as a global "any unnamed call may be BigInt" flag corrupted the parser (PLAN.md:679-680); a per-callable contract has no global flag, but a closure set that escapes past `SET_MAX` behaves like one: its callers see ANY and box everything; the kernel's `HANDLER` tables have well under 32 members, the JSON/printer visitor tables should be checked.

4.8 **Ordering of closure plans.** Closures mint their plan at emit, after every named caller has emitted (compile/index.js:426, :447-461); `recordClosureCallRepresentations` (call-args.js:37-46) exists to hand the closure facts its callers saw. A contract frozen in the summary removes the dependency, but `analyzeClosureBodyForEmit` (closure-emit.js:121-203) still seeds parameter kinds from `ctx.closure.paramTypes` (:79-84) built by `tryDirectClosureCall` (emit/call.js:212-234); the summary's `paramKindOf` in the closure scope must win there (today `localReps.val` set from the lattice wins, closure-emit.js:99), or a closure body will read a parameter as NUMBER the summary knows is {NUMBER, BIGINT} and skip the tag test.

4.9 **Census presence vs summary presence.** `censusMaybeUndefinedKind` (dict-census.js:256-288) is consulted at 30+ emit sites for dict/Map reads and mayBeUndefined names; the summary carries presence per cell (`orAbsent`, `elemOf`, query.js:171, :205). Where the two disagree (a dict receiver the census tracks by name but the summary joined into a cell with a present store), a contract that reads only the summary changes `=== undefined` folds; test/dyn-keys.js and test/data.js:1412-1545 (Set/Map) pin those.
