# Changelog

## Unreleased — v1 preparation

- Version a function's kernel loops past its growth budget (`src/growth.js`): a loop that calls nothing but the math kernels, the integer conversion and remainder, and a throw takes its integral, counted-loop, unswitched, kind-split, specialized, wide-accumulator and typed-parameter versions in a function of any size, while a loop that calls keeps the budget. TurboFan's time follows the bytes alike for dispatch and numeric code (about 2 ms a kilobyte: watr's `normalize` 125 ms at 53.7 KB, the waves example's `frame` 90 ms at 37.9 KB), so what decides is what a version buys: watr runs no faster for `normalize`'s versions with the baseline tier off (1.72 ms with them, 1.66 without), while `frame` takes 0.77× the CPU time with its own. The waves module is its unbudgeted 55.6 KB again (67 f64x2 operations where the budget left 35); watr, webaudio and polytri are byte-identical, stdlib-dists and stdlib-special 0.7 KB larger (`ibetaImp`'s integral versions) and unchanged on the x64 runner (1.000×, EPYC 9V74, seven paired rounds); every size build is byte-identical.
- Advance an address affine in a loop counter as a pointer at the speed tier (`watrLsr`, the `lsr` pass of watr 5.11.11, which jz now takes): a record stride (`rows[i]` at 20 bytes), a scale past 8, an index summed from several values, kept only where it lowers the instructions an iteration executes (one lea already forms base + index·{1,2,4,8} + displacement) without pushing integer values past the register file, its setup spread over four iterations; an inner loop's pointers start from the outer loop's. On the x64 probe (paired against the parent commit, six rounds): blur 0.83× (EPYC 7763) and 0.93× (EPYC 9V45), fftplan 0.84× and 0.89×, provenance 0.93× and 0.92×, entity 0.94× and 0.99×, aos 0.96× and 1.01×, fft 0.99× and 0.98×, shapes 0.89× on the 7763 (1.02×, noisy, on the 9V45), sdf 0.99× and 1.01×; on the 7763 bezfit 1.01×, matmul 1.02× and sieve 1.04× (spreads 0.99–1.03 and 0.99–1.05; 1.00× in earlier runs).
- Suggest the registered name nearest a mistyped optimize key by edit distance: a dropped letter (`watrLcm` for `watrLicm`) shifted every later letter of the position-by-position comparison, so a shorter, unrelated key could win.
- Test a typed-array key `a[i] + k` whole when `a[i]` may miss: the key test read `k` alone, so a missed element (NaN) plus an integer read element 0 instead of naming none (`tbl[offs[h] + v]` with a fractional `h` gave a number where JavaScript gives NaN, at every level).
- Prove a parameter integral where every direct call passes an integral Number (a floor, a remainder of one by a literal, a clamp by `Math.min`/`Math.max`, a sum of them, an integer element), and key a typed array by such parameters with one truncation and a NaN test instead of the fraction test; `Math.min`, `Math.max` and `Math.abs` of integral operands, an assignment's value (a shared subexpression's `cse = …` in place) and an integer element read inside a key count as integral too. On the x64 runner (Xeon 6973P-C, paired, five rounds) color-space's munsell, whose renotation lookups take their hue and value cells through two helpers, runs 0.81× its time (33.7 → 27.2 ms; 0.62× V8, 0.93× bun, 1.02× JavaScriptCore); the other color-space cases are unchanged (hct's module is byte-identical).
- Take a lane loop's fifth root (the `x ** 2.4`-style k/5 powers, the sRGB decode over a buffer) two lanes a step: the seed a lane at a time, then the scalar's four Newton steps on both lanes at once, so the two lanes share each step's division and keep the scalar's bits. On the x64 runner (EPYC 9V74, paired, five rounds) color-space's ipt runs 0.87× its time (25.7 → 22.3 ms; 0.76× V8, 0.81× JavaScriptCore, 0.77× bun), a98rgb 0.87×, jzazbz and jzczhz 0.92×, cam16 0.92×, hct 0.95×; checksums unchanged.
- Vectorize a per-pixel loop that calls `Math.sign`, takes a float remainder (`%`) or a `copysign` (the sign of an inline remainder): `Math.sign` two lanes wide selects each lane's own answer, the remainder takes `__rem`'s two inline answers where both lanes lie below twice their divisors and `__rem` a lane past them, `copysign` is a select of the sign bit; every lane is the scalar's bits. color-space's cam16 (its CAM16 pass: copySign, hue wraps, atan2, cos, pow) runs 0.66× its time on the x64 runner (EPYC 9V74, paired, five rounds: 19.8 → 13.1 ms; 0.55× V8, 0.62× JavaScriptCore, 0.60× bun); the other color-space cases are unchanged.
- Bind an array pattern over a call to a tuple function the compiler keeps as a function (`const [x, y] = cell(k, v, C)`, the callee called from several sites) to the call's results: the pattern's names take them as they come off the call, with no array made and read back, and a frame that destructures that way has nothing to give back. The speed tier's float range fold reads a local such a result sets as unbounded, where it read the set's absent value node. On the x64 runner (EPYC 7763, paired, five rounds) color-space's munsell runs 0.79× its time (43.2 → 34.0 ms; 0.89× JavaScriptCore and 0.87× bun, where it was 1.13× and 1.12×), hct 0.97×; the other color-space cases are unchanged.

- Stop the speed tier's copies growing a function once it is large (`src/growth.js`): past 3000 source nodes a function takes no more of the plan's loop copies (unswitched, kind-split, integral and counted-loop versions, the recurrence, stencil, row-pad, char-scan and typed-array unrolls) and no splice of a body a second site or an export keeps; the optimizer specializes a loop, versions a wide accumulator or unswitches a typed parameter only where the function stays within 13000 IR nodes with it, and past them keeps its `__ptr_offset` calls. watr's `normalize` is 28 KB of wasm instead of 55 KB, webaudio's module 1.11 MB instead of 1.38 MB (`main` 31 KB instead of 146 KB), polytri's 80 KB instead of 98 KB; the other 72 speed builds and every size build are byte-identical. On the x64 runner watr's median falls from 6.6 to 5.4 ms in the 76-case spread (per round 0.78×, 0.78×, 1.18×; V8 3.0 ms) and from 6.4 to 5.1 ms in a five-round run, and stays at 3.4 ms (1.01×, nine rounds) on a faster runner; peak RSS falls from 127 to 94 MB for watr, from 115 to 110 MB for webaudio and from 85 to 71 MB for polytri, both at the same speed. The spread's geomean is 1.001×.
- Compact a loop's kept memory once it holds two megabytes beyond twice what the last walk reached, not sixteen (`optimize.compactSlack` sets it): the churn stays in the cache. On the x64 runner (paired, five rounds) json runs 0.66× its time (0.27 → 0.18 ms, 1.11× JavaScriptCore where it was 1.69×), watr's peak RSS falls from 144 to 128 MB and tokenizer's from 76 to 62 MB; a loop of fresh JSON or a growing string holds 4 MB of memory over 60,000 iterations where it held 34. Sieve, vm and the 77-case spread move within the runner's noise.
- Compare a substring in place (`cur.substr(idx, l) === word`, a parser's keyword scan) with each side's storage decoded once, an inline string's units read off its payload and any other's at its offset, instead of two `__char_at` calls per unit: 442k such calls per jessie run go.
- Count a negative `substr` start from the end, read a negative length as empty and stop the end at the length (Annex B B.2.2.1), materialized or compared in place: `'hello'.substr(-3, 2)` gave `''` and `s.substr(2, -1)` a swapped range.
- Rewrite only the holes of a value copy (`[';', a, ...items]`, `Array.from`, a spread into a call): the pass after the block copy tests each slot and stores `undefined` where it finds a hole, no call per element and no store for a present one. subscript's ASI layer spreads the statements it has read into each new list, 166k elements per jessie parse, each of which went through `__arr_value`.
- Add a sum whose operands the summary holds to numbers, booleans and missing values as numbers, each mixed side converted in line (true 1, false and null 0, undefined NaN): no ToPrimitive and no concatenation can come of it. subscript's `idx += l` (`l` a predicate's `true` or an escape's length) made 19k `__add_slow` calls per jessie parse, each with an object and a string test.
- Pop a known array by storing the new length through the header its forwarding hop already resolved, not through `__set_len`, which read the tag and chased the forward again: one call less per `pop()` of a work stack.
- Read an array pattern over a value the summary admits an array among other kinds (`let [kind, ...node] = n` over a tree of strings and arrays, a parameter of every kind) by position behind `Array.isArray`, the protocol kept for every other value: the cursor opens only where the test fails, a rest is a copy. A kernel destructuring such values runs 1.35× Node where it ran 3.07× (interleaved); watr's run opens 8.8k cursors and collects 0.8k rests instead of 17.9k and 5.8k.
- Compare a string's unit with a one-character literal (`s[i] === '$'`) by one inline unit read: the read answers 0 past either end, which no literal but NUL equals, so the length call and the char call go (one call at the size tier). A kernel of such tests runs 1.3× Node where it ran 5.2× (interleaved, loaded machine); watr's run makes 20k `__char_at` and 118k `__str_length` calls instead of 203k and 301k.
