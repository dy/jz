Compile JavaScript to WebAssembly

Keep your numeric code in JavaScript. JZ compiles it to WASM, without type annotations. Start with one function.

Install

npm install jz

Or try the online compiler without installing anything.

Compile and call

distance.js

export const dist = (x, y) => (x*x + y*y) ** 0.5

run.mjs

import { readFile } from 'node:fs/promises'
import { compile } from 'jz'

const source = await readFile('./distance.js', 'utf8')
const wasm = compile(source)
const { instance } = await WebAssembly.instantiate(wasm)

console.log(instance.exports.dist(3, 4)) // 5

Run node run.mjs from the folder containing both files. Your fallback is the original file: import { dist } from './distance.js' and call it as ordinary JavaScript.

To compile ahead of time, use npx jz distance.js -o distance.wasm. Ship the WASM file; the compiler can stay in your build step.

Pass arrays

For arrays, strings and objects, use JZ's wrapper to move values across the JS/WASM boundary.

import jz from 'jz'

const { exports, memory } = jz(`
  export const sum = a => {
    let total = 0
    for (const x of a) total += x
    return total
  }
`)

console.log(exports.sum(new Float64Array([1, 2, 3]))) // 6
memory.reset()

Heap allocations accumulate until reset. Reset only after a batch is finished: it invalidates previous WASM pointers and views. For prebuilt modules, use instantiate from jz/interop. See the memory contract.

Choose the right work

JZ is experimental. Start with numeric loops, image processing or simulations; keep DOM and Node APIs in your host app. It implements a JavaScript subset, with documented semantic differences. Run your existing tests against both versions and measure the whole call, including data transfer.
